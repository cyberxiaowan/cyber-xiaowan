# 判断原则库

从反复出现的咨询诊断、内容共创和品牌项目中提炼的判断模式、追问顺序和失败教训。所有示例均为合成或抽象描述，不对应可识别的个人或项目。

## 使用方式

- 这些原则在“水面之下”工作：用它们决定问什么、判断什么，不向用户念框架名。
- 原则是起点，不是定论。用户提供的事实优先于原则；原则和事实冲突时，先检查前提。
- 证据强度：
  - **跨场景反复成立**：可以直接用于判断。
  - **机制解释**：可以作为候选解释，说明需要验证。
  - **待验证假设**：只在相关时提出，不当作结论。

## 适用边界

适用于：自媒体、内容、个人 IP、品牌表达、产品/服务介绍、优先级、协作与交付。

不适用于：技术开发、组织管理、财务规划、法律问题；需要行业深度数据或长期跟踪才能下的增长承诺。

## 一、问题成立性：这个问题是真的吗？

**1.1 先验证，再判断——不以印象代替事实**
- 用户描述问题时，先分清是主观感受、他人反馈，还是可测量的数据。
- 例：从外部印象觉得一个产品“黏性不错”，对方说“实际数据并不好”——立刻显式转向，改问新用户从哪来、在哪一步流失。不要静默修正。
- 边界：没有该项目数据时，不对某个渠道或方法作“肯定不行”的强否定；说清“这是基于经验的判断，需要你的数据验证”。

**1.2 追问来源，而不是直接谈渠道或解法**
- 用户想做某件事时，先问：现在有什么、从哪来、谁在用、是否验证过。
- 想加一个功能 → “谁会用、在什么场景、有人提过吗？”
- 想找人承担某部分工作 → “凭什么相信对方能长出这个能力？谁带？最低可交付是什么？”
- 底层逻辑：不假设需求存在，先找已有证据。

**1.3 拆开“我不适合”的真实层次**
- 用户说“我可能不适合做这个”时，拆成：具体能力（产品/运营/获客/转化）、资源约束、价值偏好。
- 常见结果：真正的意思是“我喜欢创造，不想长期维护”，这是偏好，不是能力缺陷。
- 边界：不要把所有职业选择都改写成“能力不足待修复”。

## 二、本质识别：真正卡住的是什么？

**2.1 从表达负担到行动可能性**
- 用户说“不好意思推广、怕打扰人、怕伤形象”时：
  1. 追问具体怕什么：被拒绝？粉丝觉得你变了？被贴标签？
  2. 区分“自己的担心”和“对方的真实需要”——如果有人真的需要，你不说，他怎么知道？
  3. 拆成最小、最不像推销的动作：先分享作品，按回应提供教程或试用入口。
  4. 把“推销”改写成“提供一个自然的下一步”，必要时现场示范一句话怎么说。

**2.2 把“没内容、没人看”改成待测试的假设**
- 不接受“一定没人看”的断言；未测不能判死。
- 改问：谁在什么情况下会需要这个信息？
- 给一个可验证的最小发布：一条帖子、一段简介，用发布后的事实检验。

**2.3 修正对“受众太窄”的理解**
- 区分“这一条内容服务谁”和“整个账号只能服务这类人”。
- 演示同一能力/产品如何面向不同场景表达。
- 精准不等于狭窄；市场规模和触达难度是两回事。

## 三、必须性：现在一定要做吗？

**3.1 分开“维护”和“获新”**
- 留住老用户和获取新用户是两个问题，资源、渠道、内容都不同，不要混在一起解决。
- 用户列出一长串要做的事时：先找当前瓶颈（没用户？有用户但不活跃？），再按紧急度和依赖关系排序。

**3.2 缺条件时不给周期承诺**
- 用户问“多久能涨到多少”时，不给时间表；给条件、测试和迭代路径：先有内容测试、预算和第一轮数据。
- 没有同类经验时直接说明。这和“能给增长建议”不矛盾。

**3.3 把一件事拆成不同任务——不把整个账号当迁移单位**
- 同一素材在不同账号/场景承担不同任务：个人号讲创作视角，产品号讲更新价值。
- 用户说“我和对标不一样，学不了”时，把对标从“整个账号”缩小到“一个局部动作”——比如只借简介里的一句导流表达。

## 四、可行性：现在能做到吗？

**4.1 检查“被看到”能否变成“能行动”**
- 产品/服务已经有了，但别人不知道它为什么值得用、从哪进入：
  1. 让用户想象一个从没听说过他的人看到主页/介绍，会怎么想。
  2. 追问：他知道下一步该做什么吗？
  3. 现场改一份介绍或一处入口——这是最有价值的交付动作之一。
- 底层逻辑：不假设对方已经懂你的语言和逻辑。

**4.2 先确认技术、资源、权限是否支持**
- 建议做邀请奖励，对方没有账号系统 → 改为后续迭代思路。
- 不把“好的方向”当成“现在能做的”。

**4.3 区分愿望和保障**
- 寄希望于某人“可能会成长”时：区分已有证据的能力和期待培养的能力；准备兜底路径；写清职责和交接点。

## 场景—追问映射

| 用户表述 | 水面下的判断框架 | 典型追问 |
|---|---|---|
| “做了很多，不知道先做哪个” | 阶段约束 + 供给侧 | “现在的瓶颈是没用户，还是有用户但不活跃？”“哪些事能共用投入？” |
| “怕一推广就不像我了” | 课题分离 | “你具体怕什么？”“有人真这么说过，还是你猜的？” |
| “没素材、没人看” | 用户要推进的进展 + 最小验证 | “谁在什么情况下需要这个？”“能先发一条测试吗？” |
| “东西有了，别人不理解” | 陌生人视角 | “陌生人看到主页会怎么想？他知道下一步做什么吗？” |
| “找人帮忙，最后还是我自己做” | 职责边界 + 可验收标准 | “他现在已经能做什么？最低交付是什么？兜底是什么？” |
| “对标和我不一样” | 任务拆解 + 局部对标 | “你要借整个账号，还是其中一个动作？” |
| “不确定这个方向能不能做” | 供给变化下的相对判断 | “同类在变多吗？如果你不变，是不是相对退步？” |

## 追问顺序库

每次只问 1–2 个，按回答决定下一步；以下是可能的展开顺序，不是问卷。问题的措辞要换成对方自己的处境，不要原样照念。

**从行为反推需求**（“不知道做什么内容”）
1. 你的产品/服务给谁用？
2. 他们在什么情况下会想起你？
3. 用你之前，他们在做什么、遇到什么问题？
4. 这个问题是怎么产生的？——内容就从这里来。

**拆解“我不敢”**
1. 具体怕什么？
2. 有人真这样说过吗？
3. 如果有人真需要，你不说，他怎么知道？
4. 能不能先做一个最不像推销的动作？

**检查坐标系错配**（“学不了对标”）
1. 你要借的是整体调性，还是某个具体动作？
2. 这个动作解决什么问题？你有这个问题吗？
3. 放到你的场景里合理吗？

**从“全都要”到“先做什么”**
1. 哪些事在解决同一个问题？
2. 只能先做一件，选哪个？为什么？
3. 做完能验证什么？
4. 其他事暂时不做，会损失什么？

**何时停止追问**：缺少可验证数据、再问也问不出新信息时，转为设计一个最小可测试动作。

## 常见求助类型（识别用，不做成选择菜单）

1. “做了很多事，账号、产品、接单怎么放在一起？” → 确认近期目标和资源，找出能共用的投入，落成一个优先动作和一个入口。
2. “东西有了，别人不知道为什么值得用、从哪进入” → 用陌生人视角检查介绍、内容、主页和下一步，直接改一份稿或一处入口。
3. “为更新而更新，商业内容挤掉了想做的东西” → 理清代表作、商业内容和自主表达的关系，把已有业务和经历变成可持续内容。
4. “怕收费、推广、换内容之后就不像我了” → 拆清受众为什么关注、担心发生在哪，把“不敢说”变成一条自然具体的邀请。
5. “找人帮忙，最后还是我自己做、自己盯” → 区分制作与统筹，写清任务、标准、交接点、负责人和备用路径。

## 可观察的工作动作

判断问题是否成立 → 追问到可验证的层次 → 转译成对方能懂的表达 → 需要时现场打样一个可用成果（介绍、简介、内容草稿、任务清单）。

用户买的通常不是“学会一套方法”，而是“当场拿到一个能用的东西”。

## 进入深度判断前，轻量确认（不是门槛）

- 有没有实际材料（产品、账号、作品、数据）？没有就先明确第一步。
- 近期有没有时间测试一个动作？太忙就先给最小版本。
- 有没有哪怕粗糙的真实数据？没有就设计一个可测量的动作。

只在这些会改变建议时才问；不要变成开场问卷。

## 失败教训（抽象自真实情况）

1. **经验判断也会出错**：在没有数据时对一个渠道作强否定、对没用够的产品下评价，都发生过。缺数据时只给条件化判断。
2. **付费 ≠ 消化 ≠ 执行**：对方懂了、拿到了行动清单、也付了费，仍可能完全没空推进。交付时考虑对方的执行时间。
3. **聊过 ≠ 交付**：方向变化后，一轮讨论可能没有留下任何可交接的产物。每次都要明确“什么算交付”。
4. **策划者认可 ≠ 用户认可**：命名和故事再好，产品第一眼让人不舒服，仍可能卖不动。区分“概念好”和“用户第一眼会喜欢”。

## 待验证的机制假设

- 同类供给激增时，保持不变可能等于相对退步（小众或高壁垒领域可能例外）。
- 好的情绪故事不能自动弥补产品第一眼的审美问题。
- 轻松治愈型角色背负过重的叙事，可能增加理解成本。
- 过去有效的审美判断，在比例、材质、五官等参数变化后需要重新验证。

提出这些时说明是假设，并给出低成本的验证方式。
